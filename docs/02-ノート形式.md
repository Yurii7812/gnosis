# 02 ノート形式

## 標準ノート

```markdown
---
time: 2026-09-27 03:35:06
---

# ノート名

本文。ここにリンクを書く。書いたリンクが「子」になる。
[別ノート](260927033509.md) の話…

### Context
[親ノート](index.md)
BackLink:
[このノートを参照しているノート](260927000000.md)
```

本文が**散文で終わっている**ときだけ、`### Context` の直前に空行が 1 つ入る。
本文が**リンク行で終わっている**ときは（リンク群のあと）空行を挟まず `### Context` が来る。
既に空行があれば重複しない（sync は本文の空行をそのまま通す）。

```markdown
# ノート名

本文だけ書いて終わるノート。

### Context
[親ノート](index.md)
BackLink:
```

`za` / `zp` / `\p` / `zn`（`Enter`）がリンクを本文に置いたときは
**リンク行で終わる**ので `### Context` は直前に続く（空行を挟まない）。
Enter で連続で 3 本置いても、**リンク同士の間には空行を入れない**
（1 つの連続ブロックとして扱う）。空行が累積しないこと。

```markdown
# ノート名

本文だけ書いて終わるノート。

### Context
[親ノート](index.md)
BackLink:
```

### ルール

- **題**: 先頭の `# 見出し`（H1）が題（2026-10-23〜）。front matter の `title:` はもう書かない。古いノートに残っていれば、H1 が無いときだけ読み、
  同期（保存のたび）が `title:` を消して、H1 が無ければ題から H1 を入れる。一度に全部直すには `python/title_migrate.py ROOT [--dry-run]`
  （`title:` と H1 が違うノートは H1 を正にして、一覧を返す。本物の vault はバックアップしてから）。
- **front matter**: `time`（作成時刻）。グループは `attribute: group`。ノートに書くよみ（表示名ごと）は front matter ではなく vault の `.gnosis/yomi/`（§よみ）。
- **本文（`# タイトル` の下）**: 自由。ここに置いた `[表示名](xxx.md)` が「子（outgoing）」。
- **`### Context`**（旧 `### Parent`）: 文脈（上位）となるノートへのリンク。**手書きで管理**する（書いたまま。同期は追加も削除もしない）。
  - 空行やメモ書きなど、リンク以外の行も保持される。
  - 置くのは**普通のノート**へのリンク。**グループ**（`attribute: group`）へのリンクは、次の `### Group` に sync が自動で移す（手で Context に書いても、保存のたびに Group へ移る）。
  - リンク行の**表示名だけ**は、相手のタイトル変更に追従して更新される。
- **`### Group`**: 所属するグループ（`attribute: group` のノート。`index.md` も含む）へのリンク。**グループが無ければ見出しごと出ない**。
  - Context に書いたグループへのリンクは、sync がここへ移す。逆に、グループでなくなったノートへのリンクは Context へ戻る。
  - **グループの本文に自分へのリンクがあれば、そのグループが自動で Group に入る**（グループの本文からリンクを消せば、Group からも外れる）。
  - 見出しの手書きは不要。`### Context` と `BackLink:` の間に置かれる。
- **`Related:`**: 横のつながり（関連）のリンク。**対称**で管理する。
  - `zr`（`za` / `zA` / `zp` の位置キーで `r`）を押すと、**両ノートに相互に** 1 本ずつ書く。
  - 見出しは `### Group` と `BackLink:` の間。**無ければこのときだけ作られる**
    （同期は勝手に作らない）。中身が空になれば同期が見出しごと外す。
  - 同期は対称性を保つ: **片側にしか無いリンクは次回同期で外される**
    （片側で消せば、もう片側からも消える）。
  - リンク行の表示名は相手のタイトル変更に追従する。
- **`BackLink:`**: 本文でこのノートにリンクしている相手（incoming）から `Context` / `Group` にあるものを除いた一覧。自動生成。
- セクションの並びは **`### Context` → `### Group` → `Related:` → `BackLink:`**。
- **関係の節は、中身があるものだけ書かれる**（空の節は見出しごと無い）。新しいノートは本文だけで、リンクができたときに sync が見出しを作り、リンクが無くなれば見出しも消える。Vim のキー（`za` / `zn` など）も、足すときに必要な見出しを作る。
- 旧 `### Parent` は読み込みで `### Context` として扱い、次の sync で書き換える（グループは Group へ振り分ける）。
- **`### Child` は存在しない**（廃止）。子は本文リンクで表す。
- 見出しは **`#` 3つ**（`### Context` / `### Group` / `BackLink:`）。本文中の `##` 見出しと衝突しないため。

## 見出しアンカー（`#スラッグ`）

リンク先を `[表示名](xxx.md#スラッグ)` とすると、そのノート内の**見出し**を指せる
（通常の Markdown のアンカーリンク。GitHub / VS Code のプレビューでも動く）。

- `zo` … カーソル下の `.md` リンク先ノートの見出しを fzf で選んで `#スラッグ` を付ける
  （右ペインに選んだ見出し以降の本文プレビュー。先頭の「（見出しなし）」で解除）。
  タイトルと同じ H1 と `### Context` / `Related:` / `BackLink:` は一覧に出ない。
- スラッグは **GitHub 互換**（`github-slugger` の近似）。小文字化・記号除去
  （ASCII 句読点と日本語の約物。`-` `_` は残す）・空白→`-`。日本語はそのまま残る。
  例: `## 私の考え (2026)` → `#私の考え-2026`。重複見出しは GitHub と同じ `-1` `-2`。
- 開くとき（`<CR>` / `1`〜`9` / `<Space>` ポップアップ）は「スラッグ一致 → 生見出し一致 →
  `<a id="...">`」の順で探す。生見出し一致があるので手書きの `#見出し` も開ける。
  `\e` の展開（`.trash/T_*.md`）の目次 `[タイトル](#note-N)` もこれで開ける。
- 同期は `#` 以降を無視して**ファイルへのリンク**として扱う（子・Parent・Related・
  BackLink・掃除・タイトル追従は今までどおり。本文/Parent/Related では `#` は保持される）。
- **`BackLink:` は同期が行を作り直すため `#` は消える**（BackLink 内では `zo` できない）。
- 見出しを Vim で書き換えて保存すると、同じフォルダのほかのノートの `[表示名](xxx.md#古いスラッグ)` も新しいスラッグに直る（`gnosis#heading_links_after`。見出しを足した・消したときや、外から書き換えたときは直らない。その場合 `<CR>` で開くと先頭＋メッセージ）。曼荼羅の `\l` → `g` → `t` で入れるリンクもこれで追従する。

## グループ（index など）

`index.md`（グループ、`attribute: group`）は**セクションを持たない**。

```markdown
---
time: ...
title: Index
attribute: group
---

# Index
[日記](260909105059.md)
[ハーブ・薬草](260912101537.md)
```

- 本文の `.md` リンクが「子」になり、**リンク先の `### Context` に Index が入る**。
- `### Context` / `BackLink:` の見出しは置かない。

## よみ（yomi）

Index のリンクを**表示名のよみ順**に並べ替えるためのよみ。2026-10-23〜 ノートの YAML ではなく、vault の
`<vault>/.gnosis/yomi/<2桁16進>.jsonl` に持つ。ノートのファイル名のハッシュで最大 256 個に分ける JSON Lines
（100 万ノートでもファイルは最大 256 個）。1 行 1 件、ノートのファイル名の順に書くので、git で同期しても行単位でマージできる。

```json
{"n":"261019143158.md","k":"筋トレ","y":"きんとれ"}
```

- `n` は vault からのノートの相対パス、`k` はリンクの**表示名**、`y` はよみ（ひらがな / カタカナ / ローマ字）。
- **漢字を含む表示名だけ**よみを聞く・書く（ひらがな・カタカナ・英数字だけの名前は、そのまま並べ替えに使える）。
- `\S` のソート時に未登録の表示名のよみが pykakasi で自動追加される。`zy`（空欄から）/ `zY`（現在のよみを残して）で手動登録/修正/削除できる
  （誤読もある。`筋トレ`→`すじとれ`）。表示名 1 つにつき 1 つのよみ。同じノートに複数あるときは番号で選ぶ。
- 書き込みは一時ファイルに書いてから置き換える（途中で壊れない）。空になった殻のファイルは残さない。
- 古い形（ノートの front matter の `yomi:` マップ）も読める。同期が見つけたら JSON に移して YAML から外す。
  一度に全部移すには `python/yomi_migrate.py ROOT [--dry-run]`（本物の vault はバックアップしてから）。
- どこからもリンクされなくなった表示名・無くなったノートのよみは、同期（`simple_sync`）が間をあけて（10 分おき）掃除する。
- 詳細は `04-キー操作.md`（`\S` / `zy`）と `06-引き継ぎ.md`。

## 命名・構造の慣習

- ファイル名はタイムスタンプ（`YYMMDDHHMMSS.md`）。タイトルは先頭の `# 見出し`。
- タイトルを変えてもファイル名は変えない（リンクはファイル名を指す）。
- 1ファイル=1ノート。アトミックにしすぎず、文章として書く。
