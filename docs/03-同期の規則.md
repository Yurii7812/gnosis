# 03 同期の規則

同期エンジン: `python/note_format_v2.py`
モード: `update ROOT`（全体）/ `update_one FILE ROOT`（保存時）

> **実体は `simple_sync()`**（同じファイル内の旧 v2 エンジン `sync_vault()` は
> `update` から呼ばれない。`sync_vault` を直して直したつもりになっていた、という
> 間違いになりやすい。`migrate` だけが `sync_vault` を呼ぶ）。
> `Parent` を「手書きで保持」しているのは `simple_sync` 側の
> `_preserve_parent()`。空行の整形は `_simple_render()`。

## 用語

- **incoming(X)**: 本文で X にリンクしているノートの集合（＝X を参照している側）。
  `### Related` のリンクは incoming には数えない（片側だけの関連が BackLink に
  現れないようにするため）。
- **outgoing(X)**: X の本文または `### Related` に書かれているリンク先の集合
  （＝X が参照している側）。

## Context と Group（`### Context` / `### Group`）

旧 `### Context` を、普通のノート向けの **Context（文脈）** と、グループ向けの **Group** の 2 節に分けた。
旧 `### Context` は読み込みで Context として扱い、次の sync で書き換える。

- **手書き管理**。ユーザーが `### Context` に書いたリンクをそのまま保持する。
- 同期は **追加も削除もしない**（消せば消えたまま）。**例外は下の 3 つ**:
  1. **仕分け**: `### Context` に書かれた**グループ**（`attribute: group` / `index.md`）へのリンクは
     `### Group` へ移す。`### Group` にあるリンクが、グループでないノートへのものなら `### Context` へ戻す。
  2. **グループからの自動追加**: グループの**本文に自分へのリンクがある**と、そのグループが自動で
     `### Group` に入る（グループの本文からリンクを消すと、Group からも外れる）。
     `index.md` の本文にあるノートは、Group の先頭に `[Index]` が入る。
  3. **消えたファイルの掃除**（下記）。
- リンク行の**表示名だけ**、リンク先の現在のタイトルに更新する（行はそのまま）。
- 空行・メモなどの非リンク行は保持。仕分けで行を動かしたときだけ、その節の先頭・末尾の空行と連続した空行を整える。
- **関係の節（Context / Group / Related / BackLink）は、中身があるものだけ**書く。空の節は見出しごと出さず、新しいノートは本文だけのまま（末尾の空行＝書き出しの余白も残す）。
- セクションの並びは `### Context` → `### Group` → `### Related` → `### BackLink`。
- 同じグループが Group に 2 本重なったら 1 本にする。冪等。
- 実装: `simple_sync()`（`note_format_v2.py`）。キャッシュ `.pkm_parse_cache_v2.json` は 8 要素（Group を含む）。
- **例外（消えたファイルの掃除）**: リンク先の `.md` が存在しない行は、sync が
  **行ごと削除**する（下記「消えたファイルへのリンク」）。

## Related（`### Related`）

- **対称管理**。`zr`（`za` / `zA` / `zp` の位置キーで `r`）を押すと、今のノートの
  `### Related` に相手、**相手の `### Related` に今のノート**を書く（相互）。
- 見出しの位置は `### Group`（無ければ `### Context`）と `### BackLink` の間。無ければ `zr` のときだけ作る。
- 同期は **リンクを追加しない**。するのは次の 4 つ:
  - リンク行の**表示名**を相手の現在タイトルに追従（`Parent` と同じ）。
  - 存在しない `.md` へのリンク行の**掃除**（行ごと削除）。
  - **対称性の維持**: 相手側の `### Related` に自分が無いリンクは**外す**
    （`_prune_one_sided_related()`）。片側で消せば次回同期で反対側からも消える。
  - 中身が空になった `### Related` 見出しの**削除**。
- 関連リンクは incoming に数えない（相手の BackLink には出ない）。ただし
  outgoing には数えるので、相互に関連を書いたペアは BackLink に重複して現れない。
- 実装: `simple_sync()` が `related` を parse → `_preserve_parent()`（表示名追従）→
  `_prune_dangling()` → 対称性フィルタ → `_simple_render()`（中身があるときだけ
  `### Related` を描画）。JS 移植 `web/src/sync.js` も同じ。

## BackLink / グループからのリンク

- `BackLink(X) = incoming(X) − Context(X) − Group(X) − {X} − outgoing(X)`
  - **`− outgoing(X)`**（2026-09-27 追加）: 自分の本文または `### Related` にも
    リンクがある相手は BackLink に出さない。本文（中央）に出ているなら BackLink は
    同じリンクの繰り返しになる。例: `A` の本文に `[B]` があり `B` も `A` を
    リンクしている → `A` の BackLink は空。
  - 本文で X にリンクしている相手のうち、X の Context に無いもの。
  - **Context にあるものは絶対に BackLink に出ない。**
- **並び順**: 既存の BackLink の順を保ち、新しく増えた分は**末尾に追加**。
- **本文でリンクしている相手がグループ（`attribute: group` / `index.md`）なら、
  そのリンクは BackLink ではなく `### Context` に入る**（containership）。
  例: `2026-09` が本文で `新PKMの設計` をリンク ⇒ 後者の Context に `[2026-09]`。
  これは sync が管理する（手書きの Context と同じ並びに追加する）。
- 表示名はリンク元のタイトル。リンク元のタイトルが変われば追従。

## 本文リンクの表示名

- 表示名が「ファイル名（拡張子なし）」と一致するとき（＝自動生成名）だけ、
  リンク先の現在のタイトルへ更新する。
- 手で意味づけた表示名（ファイル名と違うもの）は変更しない。

## 消えたファイルへのリンク（掃除）

- リンク先の `.md` が存在しないとき（ファイルを消した/改名した）、sync は残骸を掃除する。
  - **行全体がリンク 1 本の行**（`### Context` / BackLink / index 本文 / 本文の単独行）は
    **行ごと削除**。
  - **文中に埋もれたリンク**は、リンク記法だけ外して**表示名の文字は残す**
    （`以前 [AI](x.md) について` → `以前 AI について`）。文章を消さない。
  - `![alt](pic.png)` など `.md` 以外のリンクは対象外。
- BackLink は incoming から再生成されるため、元ファイルが消えれば自然に消える。
- 実装: `simple_sync()` が body / Context に `_prune_dangling()` を掛ける。

## index.md（グループ）

- `index.md` はセクションを持たない。
- 本文の `.md` リンクが子として扱われ、**リンク先の `### Context` に Index が入る**。
- **逆向きも同期する**: Index の本文に無いノートに `[Index]` が `### Context` に
  残っていたら**外す**（`zp` で足したままになった残骸を放置させない）。
  Index との対応だけは sync が管理する。 他の手書き Context（Discord など）は手書きのまま。

## いつ同期が走るか

- 保存時（autosync）
- タイトル変更後（`zt` / `zT`）… 本文・Context・BackLink の表示名が追従
- 手動: `:UpdateMD` / `:UpdateAll`（旧コマンド名）相当、`update` モード

## 例

初期:
```
A.md 本文: [B](B.md)
B.md: ### Context（空） / ### BackLink（空）
```
同期後:
```
B.md
### Context
### BackLink
[A](A.md)          ← incoming(B)={A} で Context に無いから BackLink
```

B の `### Context` に `[A](A.md)` を書くと:
```
### Context
[A](A.md)          ← 手書きはそのまま
### BackLink
                   ← A は Context にあるので BackLink から消える
```

後から `Z` が B を参照すると:
```
### BackLink
[A](A.md)
[Z](Z.md)          ← 新規は末尾
```
