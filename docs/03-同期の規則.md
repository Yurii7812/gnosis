# 03 同期の規則

同期エンジン: `python/note_format_v2.py`
モード: `update ROOT`（全体）/ `update_one FILE ROOT`（保存時）

> **実体は `simple_sync()`**（同じファイル内の旧 v2 エンジン `sync_vault()` は
> `update` から呼ばれない。`sync_vault` を直して直したつもりになっていた、という
> 間違いになりやすい。`migrate` だけが `sync_vault` を呼ぶ）。
> `Parent` を「手書きで保持」しているのは `simple_sync` 側の
> `_preserve_parent()`。空行の整形は `_simple_render()`。

## 用語

- **incoming(X)**: 本文で X にリンクしているノートの集合（＝X を参照している側）。
  `Related:` のリンクは incoming には数えない（片側だけの関連が BackLink に
  現れないようにするため）。
- **outgoing(X)**: X の本文または `Related:` に書かれているリンク先の集合
  （＝X が参照している側）。

## Context（本文冒頭の `Context:` ブロック）

**Context は `### Context` 節ではなく、本文の冒頭（H1 の直後）の `Context:` ブロックに保存する**（2026-10-15〜）。
`Context:` は Markdown の見出しではない、ふつうのテキスト行で、直下にリンクが並ぶ（空行か文章で終わる）。

```markdown
# ノート B

Context:
[ノート A](a.md)
[ノート C](c.md)

本文。
```

- 認識するのは H1 の直後（間は空行だけ。H1 が無ければ front matter の直後）にあるものだけ。本文の途中や、コードブロックの中の `Context:` は Context ではない。
- `c` で足すリンクは既存リンクの**最後**へ。同じノート（相対パスを解決して比べる）は重複させない。Context が無ければ H1 の直後に作る（Context を勝手に作ることはしない）。
- 新規ノート（`zn` → Enter）は `# タイトル` / 空行 / `Context:` / リンク / 空行 / **カーソル行** / 空行 の形で開き、すぐ本文を打てる。
- **旧形式 `### Context`（旧 `### Parent`）も読む。** sync は旧形式のノートを**書き換えて移行しない**（旧形式のまま書く）。新形式のブロックと旧節が両方あるときは、リンクを 1 本も失わず 1 つのブロックにまとめる。
  `c` で足したノートは、その場でリンクを失わず新形式へ移る。明示的な移行は `:GnosisContextMigrate`（今のノート）/ `:GnosisContextMigrate all`（試走）/ `:GnosisContextMigrate! all`（vault 全体。`python/context_ops.py migrate ROOT [--apply]`。移行前後のリンク集合と他の行が同じことを検証してから書く）。
- Context の意味は変わらない（`za` → `c` で A に B を足せば A の Context に B）。ParentBranch と同じノートを Context にも登録できる（別の関係）。
- `\S` のよみ順ソートは `Context:` ブロックのリンクを並べ替えない。

以下の「Context と Group」の節は、旧形式（`### Context`）の規則とグループ振り分け（Context 内のグループへのリンクは `### Group` へ）。新形式でも振り分けは同じ。

## Context と Group（`### Context` / `### Group`）

旧 `### Context` を、普通のノート向けの **Context（文脈）** と、グループ向けの **Group** の 2 節に分けた。
旧 `### Context` は読み込みで Context として扱い、次の sync で書き換える。

- **手書き管理**。ユーザーが `### Context` に書いたリンクをそのまま保持する。
- 同期は **追加も削除もしない**（消せば消えたまま）。**例外は下の 3 つ**:
  1. **仕分け**: `### Context` に書かれた**グループ**（`attribute: group` / `index.md`）へのリンクは
     `### Group` へ移す。`### Group` にあるリンクが、グループでないノートへのものなら `### Context` へ戻す。
  2. **グループからの自動追加**: グループの**本文に自分へのリンクがある**と、そのグループが自動で
     `### Group` に入る（グループの本文からリンクを消すと、Group からも外れる）。
     `index.md` の本文にあるノートは、Group の先頭に `[Index]` が入る。
  3. **消えたファイルの掃除**（下記）。
- リンク行の**表示名だけ**、リンク先の現在のタイトルに更新する（行はそのまま）。
- 空行・メモなどの非リンク行は保持。仕分けで行を動かしたときだけ、その節の先頭・末尾の空行と連続した空行を整える。
- **関係の節（Context / Group / Related / BackLink）は、中身があるものだけ**書く。空の節は見出しごと出さず、新しいノートは本文だけのまま（末尾の空行＝書き出しの余白も残す）。
- セクションの並びは `ParentBranch:` → `### Context` → `### Group` → `ChildBranch:` → `Related:` → `BackLink:`。
- 同じグループが Group に 2 本重なったら 1 本にする。冪等。
- 実装: `simple_sync()`（`note_format_v2.py`）。キャッシュ `.pkm_parse_cache_v2.json` は 8 要素（Group を含む）。
- **例外（消えたファイルの掃除）**: リンク先の `.md` が存在しない行は、sync が
  **行ごと削除**する（下記「消えたファイルへのリンク」）。

## Branch（`ParentBranch:` / `ChildBranch:`）

Folgezettel のような「あるノートから**直接**続くノート」を、`b`（直接の子）/ `p`（直接の親）（`zn` / `zk` / `za` / `\l` の位置キー。内部では同じ処理）で**明示**して記録する関係。
親子関係はこれまでどおり Branch リンクだけで決まり、タイトルやファイル名からは推測しない。Folgezettel ID は `folgezettel:` YAML 値として別に保存し、タイトル・ファイル名は変更しない。`Context` / `Related` とは別の関係。

```markdown
# ノート A                       # ノート B
本文                              本文
ChildBranch:                  ParentBranch:
[ノート B](b.md)                  [ノート A](a.md)
```

- **親（ParentBranch）は 1 ノートに最大 1 つ**。子（ChildBranch）は何本でもよい。
- 追加は `python/branch_ops.py`（Vim からは `gnosis#branch#*`）が行う。変更前に**両方のノートを検証**し、問題がなければ 2 つのファイルをまとめて書く
  （一時ファイル → 置き換え。片方の保存に失敗したら書いた側を元に戻す）。拒否したときは**どちらのノートも変更しない**。
  - 拒否: 子に別の親が既にある（現在の親のタイトルを表示。付け替えない・既存の親を消さない）／自分自身／循環（A → B → C → A）／index.md／未保存の編集があるノート（Vim の sync-dirty マーカー）。
  - 既に同じ親子関係があれば重複を作らない（片側だけ書かれていた場合は欠けた側だけ補う）。
  - 子が複数のとき（`za` で複数リンク）は全部を検証してから書く。1 つでも足せなければ全体を拒否する。
- 親に有効な `folgezettel` ID があるとき、新しい子の ID は既存の直接の子の最大番号の次（例: `1a` の子が `1a1` なら次は `1a2`）を付ける。ID がない親の場合はここでは付けず、あとで Index から割り当てられる。
- 通常の保存同期・`:UpdateMD` 実行時、Index に直接リンクされた親なしノートのうち ID が無いものへ、既存の数値ルート ID の最大値 + 1 を付ける（まだ無ければ `1`）。複数の未採番ノートは YAML の `time` の古い順で処理する（日時が無効・欠落なら日時形式のファイル名を使い、それも無ければ最後にパス順）。その後 Branch の子孫にも欠けている ID を兄弟ごとの作成日時順に割り当てる。Index の並べ替えで既存 ID は変更しない。
- 階層は数字と英字を交互に付ける（`1 → 1a → 1a1 → 1a1a`）。英字は `z` の次が `aa`。YAML は `folgezettel: "1a1"` のように文字列として保存する。新規孤立ノートにはまだキーを付けない。
- `:GnosisFolgezettelMove` で移動モードをON/OFFにする。ON中はステータスラインにも表示する。ノーマルモードの Ctrl＋↑は親ID、↓は最初の子ID、←／→は前後の兄弟IDのノートを開く。番号は変更しない。移動先がない場合やIDが重複している場合は移動せず通知する。
- **sync は ParentBranch / ChildBranch を追加も削除もしない**（`### Context` と同じ手書き管理）。する のは次の 3 つだけ:
  表示名の追従・消えたファイルへのリンクの掃除・空になった節の見出しの削除。`Context` へ変換しない・BackLink に出さない
  （ParentBranch の相手と ChildBranch の相手は BackLink から除く）。コードブロックの中の見出しは節として扱わない。
- 手編集で**親が複数**になったときも、sync は片方を消さない。`:GnosisBranchCheck`（`python/branch_ops.py check ROOT`）が
  「親が複数」「片側だけ」「循環」「自己参照」を報告する（何も書き換えない）。この状態のノートには Branch を追加できない。
- 同期のキャッシュ `.pkm_parse_cache_v2.json` は 11 要素（ParentBranch / ChildBranch を含む）。旧キャッシュは自動で読み直す。

## Related（`Related:`）

- **対称管理**。`zr`（`za` / `zA` / `zp` の位置キーで `r`）を押すと、今のノートの
  `Related:` に相手、**相手の `Related:` に今のノート**を書く（相互）。
- 見出しの位置は `### Group`（無ければ `### Context`）と `BackLink:` の間。無ければ `zr` のときだけ作る。
- 同期は **リンクを追加しない**。するのは次の 4 つ:
  - リンク行の**表示名**を相手の現在タイトルに追従（`Parent` と同じ）。
  - 存在しない `.md` へのリンク行の**掃除**（行ごと削除）。
  - **対称性の維持**: 相手側の `Related:` に自分が無いリンクは**外す**
    （`_prune_one_sided_related()`）。片側で消せば次回同期で反対側からも消える。
  - 中身が空になった `Related:` 見出しの**削除**。
- 関連リンクは incoming に数えない（相手の BackLink には出ない）。ただし
  outgoing には数えるので、相互に関連を書いたペアは BackLink に重複して現れない。
- 実装: `simple_sync()` が `related` を parse → `_preserve_parent()`（表示名追従）→
  `_prune_dangling()` → 対称性フィルタ → `_simple_render()`（中身があるときだけ
  `Related:` を描画）。JS 移植 `web/src/sync.js` も同じ。

## BackLink / グループからのリンク

- `BackLink(X) = incoming(X) − Context(X) − Group(X) − {X} − outgoing(X)`
  - **`− outgoing(X)`**（2026-09-27 追加）: 自分の本文または `Related:` にも
    リンクがある相手は BackLink に出さない。本文（中央）に出ているなら BackLink は
    同じリンクの繰り返しになる。例: `A` の本文に `[B]` があり `B` も `A` を
    リンクしている → `A` の BackLink は空。
  - 本文で X にリンクしている相手のうち、X の Context に無いもの。
  - **Context にあるものは絶対に BackLink に出ない。**
- **並び順**: 既存の BackLink の順を保ち、新しく増えた分は**末尾に追加**。
- **本文でリンクしている相手がグループ（`attribute: group` / `index.md`）なら、
  そのリンクは BackLink ではなく `### Context` に入る**（containership）。
  例: `2026-09` が本文で `新PKMの設計` をリンク ⇒ 後者の Context に `[2026-09]`。
  これは sync が管理する（手書きの Context と同じ並びに追加する）。
- 表示名はリンク元のタイトル。リンク元のタイトルが変われば追従。

## 本文リンクの表示名

- 表示名が「ファイル名（拡張子なし）」と一致するとき（＝自動生成名）だけ、
  リンク先の現在のタイトルへ更新する。
- 手で意味づけた表示名（ファイル名と違うもの）は変更しない。

## 消えたファイルへのリンク（掃除）

- リンク先の `.md` が存在しないとき（ファイルを消した/改名した）、sync は残骸を掃除する。
  - **行全体がリンク 1 本の行**（`### Context` / BackLink / index 本文 / 本文の単独行）は
    **行ごと削除**。
  - **文中に埋もれたリンク**は、リンク記法だけ外して**表示名の文字は残す**
    （`以前 [AI](x.md) について` → `以前 AI について`）。文章を消さない。
  - `![alt](pic.png)` など `.md` 以外のリンクは対象外。
- BackLink は incoming から再生成されるため、元ファイルが消えれば自然に消える。
- 実装: `simple_sync()` が body / Context に `_prune_dangling()` を掛ける。

## index.md（グループ）

- `index.md` はセクションを持たない。
- 本文の `.md` リンクが子として扱われ、**リンク先の `### Context` に Index が入る**。
- **逆向きも同期する**: Index の本文に無いノートに `[Index]` が `### Context` に
  残っていたら**外す**（`zp` で足したままになった残骸を放置させない）。
  Index との対応だけは sync が管理する。 他の手書き Context（Discord など）は手書きのまま。

## いつ同期が走るか

- 保存時（autosync）
- タイトル変更後（`zt` / `zT`）… 本文・Context・BackLink の表示名が追従
- 手動: `:UpdateMD` / `:UpdateAll`（旧コマンド名）相当、`update` モード

## 例

初期:
```
A.md 本文: [B](B.md)
B.md: ### Context（空） / BackLink:（空）
```
同期後:
```
B.md
### Context
BackLink:
[A](A.md)          ← incoming(B)={A} で Context に無いから BackLink
```

B の `### Context` に `[A](A.md)` を書くと:
```
### Context
[A](A.md)          ← 手書きはそのまま
BackLink:
                   ← A は Context にあるので BackLink から消える
```

後から `Z` が B を参照すると:
```
BackLink:
[A](A.md)
[Z](Z.md)          ← 新規は末尾
```
