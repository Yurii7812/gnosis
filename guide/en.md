This note is the Gnosis guide. **Part 1** explains the basics (notes, indexes, `\l` and the double-index method) in the order you actually do things, and **Part 2** explains the other features. **Part 3** is a **quick reference of every feature** with minimal explanation.
When you change the language in the settings (`:GnosisSettings`), this guide is rebuilt in that language. **Vim basics are at the end of Part 2.**

## Part 1: The basics for first-time users

This part is written so that someone who has never used Vim or Gnosis can **press the keys from top to bottom and end up with a first note and an index**. If a word is unfamiliar, just keep reading.

### 0. Before you start: for people new to Vim

- Gnosis runs inside real **Vim**, an editor you control with the keyboard alone. A note is an ordinary Markdown file, one note per file. The folder that holds your notes is called a **vault**.
- **Start**: use the desktop icon, or type `gnosis` in a terminal. Press `Enter` on the first screen to begin. The first time, press `v` and then `n` to create a new vault (the folder for your notes).
- **How keys are written**: `Enter` and `Esc` are those keys. `Ctrl-←` means holding Ctrl and pressing ←. `zn` means pressing `z` and **then** `n` (one after the other, not together). `\l` means pressing `\` (backslash; the ¥ key on a Japanese keyboard) and then `l` (the letter L).
- **Two states (modes)**: right after starting you are in **normal mode**, where letter keys do not type letters but give **commands**. To type text you enter **insert mode** (press `i`). Press `Esc` to leave insert mode. **When in doubt, press `Esc` twice** and you are always back in normal mode. Unless stated otherwise, the keys in this guide are pressed in normal mode.
- **Move around** with the arrow keys (or `h` `j` `k` `l` = left, down, up, right). **Saving is automatic** (about 1.5 seconds after you stop typing, and immediately on `Esc`). To **quit**, press `\X` (closes everything; unsaved notes are saved first).
- **When stuck**: press `Esc` twice first. If you forget a key, press `?` in the mandala or Folgezettel view (a help popup appears), or see the quick reference in Part 3.

### 1. The idea: the double-index method

- Gnosis notes are connected so that you can reach each one from **one of two kinds of index**: like a book's table of contents and its topic indexes.
- The **Global Index** (`index.md`) is the entrance to the whole vault; open it any time with `\i`. A **Topic Index** is a small entrance for one topic. You make it by branching off a note. It is also called a "group".
- The path is shown below. You go down from the wide entrance (Global) to narrow entrances (Topic), so you do not get lost even when you have many notes.

```
Global Index (index.md)
  ├─ First note "Cooking" ── Topic Index "Cooking index" ── "Curry", "Pasta" ...
  └─ First note "Reading" ── Topic Index "Reading index" ── "Novels", "Papers" ...
```

- You do not have to go through an index every time. Recent notes, full-text search (`gs`), links in the text and the mandala view all work too. The double index is the path for searching systematically.
- Notes relate in four ways. **Branch** (parent and child; this becomes the Folgezettel number), **Group** (the note is in an index), **Context** (the trigger or background) and **Related** (a paired relation). Write a link and save, and sync writes the other side (`BackLink:` and so on) for you.

### 2. Try it: making a "Cooking" note

**① Look at the screen.** After starting, the left half shows the **mandala view** (a screen for seeing how notes connect) and the right half shows `index.md` (the Global Index). The cursor is on the left, so press `Space` to move to the note window on the right.

**② Make the first note.** On the Index press `zn`. Choices appear at the bottom; press `Enter` (register), type "Cooking" as the display name and press `Enter`. A "Cooking" link is added to the Index and **a new empty note opens**. This is your first note (notes listed in the Index get the top-level numbers `1` `2` `3` …).

**③ Write the title and the body.** Press `zr`, type a title (for example "Cooking") and press `Enter`. Then press `i` to enter insert mode and write the body. When you are done, press `Esc`. Saving is automatic.

**④ Make a follow-up note (a child).** In the current note press `zn` and then `Enter` (a link is added at the end of the body). The new note opens; write its title and body as in ③. **The current note becomes the parent and the new note the child**, and the number becomes a child of the parent's (`1a`).
When the shape of the tree changes (you change a parent, delete a note and so on), **the numbers are renumbered automatically on save and gaps are closed**. You do not need to run `:UpdateMD` by hand. A note has at most one parent (any number of children).

**⑤ Make a topic index (Topic Index).** In the "Cooking" note press `zk` and then `n`. A group branching off "Cooking" is created. This is the index for the cooking topic.
**Put notes into the index**: the new group can be opened from the `BranchGroup:` link of the "Cooking" note (`<CR>`). With that index open press `zn` and then `Enter` (create a new note and register it). Or add an existing note with `\l`, `e`, `g` (explained in ⑥). You are asked for a **display name** and its **reading** (used to sort in Japanese order), and the index is sorted after you add it. Indexes can be nested (`index.md` → a topic index → an even finer index).

**⑥ Use `\l` to insert a link to an existing note.** In the note where you want the link, press `\l` (that note is the "original note"). A **screen for choosing the note to insert** appears. Choose like this:

- In the mandala view move between cells with `h` `j` `k` `l` (or the arrows) and press `Enter` to make a note the center. In the Folgezettel view use `j` `k` (up and down), `h` (parent), `l` (child) and `[` `]` (siblings). You can also pick with full-text search (`gs`).
- **You can switch between the mandala and the Folgezettel view with `Ctrl-←` / `Ctrl-→` (or `gv`) and the choosing screen continues.** `o` shows the original note on the right (press again to return to the note you are choosing).
- Press `e` for "**this one**" (in the Folgezettel view the note on the cursor line, in the mandala the center note). Press `q` to quit.
- Then you are asked **where to put it**: `Enter` end of the body / `t` under a heading / `h` under the cursor / `i` inside the line / `c` put the current note into the other note's Context / `a` put the other note into the current note's Context / `b` make it a child / `p` make it the parent / `m` merge the two notes / `g` if it is an index, put the current note into it. When unsure, press `Enter`.
- If you select part of the text first (press `v` and use the arrows) and then press `\l`, **the selected text becomes the link to that note**.

**⑦ Look and search.** `Space` moves between the left screen (mandala / Folgezettel) and the note on the right. `Ctrl-←` / `Ctrl-→` switch mandala ⇔ Folgezettel view. The mandala shows the notes connected to the center note, eight around it. The Folgezettel view is a list in number order: moving the cursor changes the note on the right too (the `▸` mark stays on the note you opened with `Enter`). `c` goes back to the mark.
`gs` searches the whole vault. `\o` shows the outline (headings) of the current note in the **right panel**. `\h` (hub) and `\q` (tab board) use the same right panel (there is only one panel; the key you press replaces its content). Press the same key again to go back and forth between the note and the panel. `q` inside the panel closes it. `Shift+→` / `Shift+←` (or `gl` / `gh`) move one window at a time between the left view, the note and the right panel. `\W` **shows only the note** (closes every window such as the mandala and the panel, wherever the cursor is). Quit with `\X`.

**⑧ Every day.** `\d` opens today's diary (and creates it if needed). Notes you create that day are listed in the diary's "today's notes" automatically. Memos from the phone are imported with `\M` over USB. Sync runs on every save, so normally you do nothing. Only when you want to tidy everything, run `:UpdateMD` (or `\ua`).

### 3. When something goes wrong

- **Keys type letters / commands do nothing** … you are in insert mode. Press `Esc`. Conversely, if you cannot type text, press `i`.
- **Too many windows and you are lost** … press `\W` to get back to a single note. You can open the mandala again later with `Space` or `\c`.
- **Made or deleted something by mistake** … `u` undoes. A discarded note can be restored from the trash with `\tr`.
- **A number looks wrong** … saving fixes it automatically. To fix existing mismatches all at once, run `:UpdateMD`.

## Part 2: Other features

### Mandala, Folgezettel and list views

- When Gnosis starts, the mandala view is shown on the left half (setting `mandalaOnStart`; change it in `:GnosisSettings`; on by default). The view you closed with (mandala, Folgezettel or list), its width and its modes are restored even after restarting Vim.
- **Moving in the mandala**: `h` `j` `k` `l` / arrows move between cells (the note on the right follows), `1`–`8` jump to a cell, `Enter` makes it the center, `Tab` / `S-Tab` go through them in order, `[` `]` switch mandala pages, `b` / `⌫` go back, `\.` undoes going back and `Space` moves to the note.
- **Mandala modes**: `a` all / `i` indexes only / `d` parent and children only / `c` near groups / `r` predicted related / `v` outward / `w` by closeness / `u` headings / `D` descendants only. `f` toggles 9×9 ⇔ 3×3, `p` hides or shows the note on the right, `L` shows the legend. `s` searches, `x` narrows, `m` highlights (`n` `N`). `q` ends stacked layers one by one and `Q` closes everything. `Z` opens the settings screen (presets with `'`).
- **Moving in the Folgezettel view**: `j` `k` move between items, `h` / `←` go to the parent, `l` / `→` go down (toward the open note if it is below), `[` `]` go to the previous or next sibling, `Enter` opens the note, marks it and **moves the cursor to that note's window** (only during the `\l` choosing mode does it stay in the view), `c` goes back to the mark and `gg` `G` go to the top or bottom. `u` is the upper view (ancestors and related groups; `M` shows more related groups).
- **The width is remembered separately for mandala, Folgezettel and list views** (a width changed with `<` `>` applies to that view only; switching restores each one's width, even after restarting Vim). When you move to the note on the right (`Space`), **the note is shown from the top and only the cursor is placed on the last line of that same screen** (the same for the mandala and the Folgezettel view; it follows the parts hidden with `\zz` and the window size; once you move the cursor inside the note it is not placed again).
- **Numbers in the Folgezettel view**: it lists the number (`folgezettel:`) and the title. If a BranchGroup shares the number, the Group row comes first and the Note row second. A long number is shortened with `~` at the front (select it to see the whole number below). When sync changes numbers, the view reloads automatically.
- Common to both views: `f` `<` `>` `=` `p` `.` are full screen, width, the right window and reload, `?` shows help, `\c` `\C` switch between the app (GUI) and the CUI, `\x` closes the current screen and `\X` closes everything. In the choosing mode (`\l`) `e` `I` `o` `q` are available.

- **List view**: `Ctrl+→` cycles mandala → Folgezettel → list → mandala; `Ctrl+←` reverses (`gv` goes forward). `1` search / `2` similar / `3` links; `s` runs the same search as gs in this list, without a popup. In search, `S` cycles All → Index names + groups → Without index names. `+` sets depth (1–10), `w` uses the mandala’s closeness order. In links, `b` children / `p` parents / `g` groups / `c` context / `r` related / `v` cited / `B` backlinks / `i` index entries / `a` all filter by relation without moving. Depth exploration is capped at 300 items.
- **Searching lists and returning**: in both list and Folgezettel views, `s` searches, `x` filters, `m` highlights, and `n` / `N` jump between matching items. Type in the bottom prompt; Enter accepts and Esc restores the previous query. In the list, `j` / `k` / arrows preview on the right while keeping the anchor fixed; Enter moves into that note. `o` restores the original note, cursor and scroll position; Backspace restores the previous exploration settings. Previewing alone does not add history.

### The right panel (outline, hub, tab board) and moving between windows

- `\o` (`:GnosisOutline`) shows the headings (`#` `##` `###` …) of the current note in the **right panel**. `\h` / `\0` show the hub (an editable list of links) and `\q` (`:GnosisTabs`) shows the tab board. **There is only one panel on the right**; the key you press replaces its content.
- **Press the same key again to move between the note window and the panel.** `q` inside the panel closes it. It is the same from the mandala view, the Folgezettel view, inside the panel and from a plain note. The hub and the board can be edited as before (saving is automatic).
- `D` inside the `\q` board **deletes all tabs** (asks once to confirm). `\Q` adds the current note to the board and `\H` adds it to the hub.
- Inside the outline: `j` `k` choose and `Enter` jumps to that heading in the body (the cursor moves there too), `za` `zc` `zo` `zM` `zR` fold, `<` `>` change the width, `s` swaps left and right and `Space` goes to the body window. It updates automatically when you edit and highlights the heading under the cursor.
- **Panel width**: inside the panel `<` and `>` mean "move the border in that direction" (the same as `<` `>` in the mandala). In the right panel `<` moves the border left, so the panel gets wider, and `>` moves it right, so it gets narrower. **Window widths never move by themselves**: opening or closing the panel does not change the width of the left view (mandala / Folgezettel); the note window absorbs the difference.
- **Moving between windows**: `Shift+→` / `Shift+←` (and `gl` / `gh` as a fallback) move one window at a time: left view (mandala / Folgezettel) → note → right panel. They stop at the ends. In Vim notation they are `<S-Right>` / `<S-Left>`. Vim's standard Shift+arrow (word movement) is replaced, but `b` and `w` do the same.
- `\W` (`:GnosisOnlyNote`) **shows only the note**. It closes the mandala, the Folgezettel view, the panel and any other split windows, leaving a single note window (the same wherever the cursor is; the mandala is remembered as closed).

### Search

- `gs` … full-text search of the vault (titles first; titles on the left, hits highlighted on the right) → `⏎` opens the hit line (`:GnosisSearch`)
- Search syntax (the same in `gs` and the mandala's `s` `x` `m`) … space = AND, a leading `-` = NOT (`ハーブ -メモ`), a `|` with spaces around it = OR (`ハーブ | バジル`), `"…"` = one term that may contain spaces, and to search for the same characters as an operator put `\` before it or wrap it in `"…"` (a `-` inside a word or a `|` without spaces is just a character). Case, full/half width and katakana/hiragana are ignored
- Search modes (shared by `gs` and normal / visual `\l`) … `Ctrl+→` / `Ctrl+↓` cycle forward, `Ctrl+←` / `Ctrl+↑` backward: All (index names, groups, titles and body text) → Index names + groups → Without index names (groups, titles and body text). The screen shows the current mode. Switching preserves the query and works with zero results. Plain arrows keep their existing behavior
- Index names … body links in groups (`index.md`, topic indexes, etc.) supply independent candidates pointing to their destination only when that destination's `Group:` lists the source group. Relation fields, code, and ordinary notes' body links are excluded. Different names for one destination stay separate; identical destination/name pairs are deduplicated. Normal `\l` inserts that display name, visual `\l` keeps the selected text. `gs` opens the destination (a name-only hit does not jump to a made-up body hit line)
- `rg` … ripgrep line search (`:Rg`)

### Making notes and links (details)

- `zn` … create a note. Choose one position key (other keys do nothing):
  `Enter`=end of the body / `t`=under a heading / `h`=below the cursor / `i`=at the cursor position (inside the line) / `c`=Context (the current note into the new note's `Context:`) / `b`=ChildBranch (direct child) / `p`=ParentBranch (direct parent) / `o`=no link (orphan) / `r`=Related (both directions)
  `Enter` / `t` / `h` / `i` / `c` also add a Branch, separately from where the link goes: the original note is the parent and the new note the child (the original note's `ChildBranch:`, the new note's `ParentBranch:`). Only `c` adds Context. `b` records only the Branch, `p` reverses its direction, `o` is an orphan. `r` adds only Related, with no automatic Branch, Context or body link. Automatic Branch and duplicate handling for notes made from the diary are unchanged
- After `c` (same in `zn` / `\l` / `za`) … the current note (A) goes into the other note's (B) `Context:`. If B has no parent (Branch) yet, A also becomes B's parent (the first Context is the parent, as in the phone memo app). Then choose where in A to put the link to B: `Enter`=end of the body / `t`=choose a heading, end of that section / `h`=below the cursor / `i`=inline (right after the character under the cursor) / `o`=do not place it anywhere / `w`=do not place it; yank B the same way as `yn` (A stays open; paste it yourself). `Esc` cancels and nothing changes (all questions come before any change)
- After `a` (`\l` / `za`; the reverse of `c`) … the chosen note (B) goes into the current note's (A) `Context:`. If A has no parent (Branch) yet, B also becomes A's parent. Then choose where in B to put the link to A: `Enter`=end of the body / `t`=choose a heading, end of that section / `o`=do not place it / `w`=write nothing in B; yank a link to A and open B (paste it with `p`; with several, open the rest with `:GnosisWNext`). `Esc` cancels and nothing changes
- `b` (ChildBranch = direct child) / `p` (ParentBranch = direct parent) (position keys of `zn` / `za` / `\l`) … with `b` the current note is the parent and the chosen (new) note the child; with `p` the chosen (new) note is the parent and the current note the child. Both use the same code and write the link into **the parent's `ChildBranch:` and the child's `ParentBranch:`**. With `p` only one note can be chosen as the parent. A note can have at most one parent (ParentBranch); children are unlimited. A note that already has a parent, a self reference, or a pair that would form a cycle is rejected and neither note is changed (the existing parent is never replaced; the current parent's title is shown). It is a separate relation from Context / Related. Check consistency with `:GnosisBranchCheck`
- `zn` on a group … `Enter`=type a display name, then create the note and add it to this group (a link with the display name in the group's body, the group in the new note's `Group:`; the new note opens and the index is re-sorted by the same rule as `\S`) / `o`=orphan (not linked anywhere; sort it out later with `\a`). Other keys do nothing. In a BranchGroup, Enter also makes the origin note the new note's `ParentBranch:`. `g` adds to the group without a parent. No Context is added. Ordinary groups and `index.md` do not assign a parent
- Adding a note to a BranchGroup with `za` also assigns the origin as `ParentBranch:` if the note has no parent; existing parents are kept. `:GnosisGroupParent off` disables this for the session, `on` restores it (also applies to `zn`; no argument toggles). For one creation without a parent, use `zn` → `g`.
- `zk` … on an ordinary note, only `n`: make a group (G) that branches from the current note (A). G goes into A's `BranchGroup:` and `ChildBranch:`, A into G's `ParentBranch:`. No Context. A group in `BranchGroup:` is not shown again in A's `Group:` (the link to A in G's body stays). `zk` cannot be used on a group (visual too)
- Relation headings use the same "Name:" form as `Group:` / `Context:` (`ParentBranch:` / `ChildBranch:` / `Related:` / `BackLink:`; empty ones are not written). The old `### Name` headings are still read and are rewritten to "Name:" at the next sync (`:UpdateAll`; no link is lost). Only the old `### Context` is moved with `:GnosisContextMigrate! all`
- Inside `BranchGroup:` the entries are simply listed from top to bottom (no link or relation is added). No indentation is used (old indented lines go back to flat on sync). Topics of the paper PKM (`\F`) go into the `BranchGroup:` of that number's scan note (after the parent topic and its children, if there is a parent)
- A note can be added to the same group under several display names. The name prompt shows when it already belongs. Its `Group:` link shows `[B:aaa]` or `[B:aaa,bbb]`, including the names used in that group.
- Deleting a group link from a note's `Group:` removes that note's link from the group's body at the next sync, so it leaves the group (it does not come back; deleting it from the group's body still removes it from `Group:` as before)
- `zk` (visual) … on an ordinary note, create a group whose content is the selection, and replace the selection with a link to the group (not on a group)
- `zh` … link right below the cursor (as body → BackLink on the other side)
- Groups (BranchGroup style) … the entry point (Index) is never replaced. For a topic index, use `zk` → `n` on the starting note. Add a note to a group with `zn` → `Enter` on the group, or `\l` → `e` → `g`

- `\L` (normal) … on a checkbox line, linkify its text as in Visual mode (keep the checkbox and indentation). Elsewhere, turn the file name under the cursor into a Markdown link
- `\L` (visual) … replace the selection with a link to a new note named by the selection (the new note's title stays the timestamp). It first asks how to connect: `b`=Branch (the new note becomes a child of the current note) / `c`=Context (the current note goes into the new note's `Context:`; with no parent it also becomes the parent) / `Enter`=no relation (the original note only shows up in BackLink) / `Esc`=cancel
- `\p` (normal) … add one link from under the cursor or the clipboard (choose the position with `h`/`Enter`)
- `\p` (visual) … turn the selection into a link to the clipboard file name / URL (nothing if there is none)
- `za` … add the copied / yanked links to the current note (all lines, all links). Same position keys as `\l` (`Enter` / `i` / `t` / `h` / `c` / `b` / `p` / `r`, and `g` puts the current note into the chosen group). `Enter` only puts the link at the end of the body; it never adds the note to a group, even if the target is a group
- `zA` … like `za`, but asks for the **display name** first (empty Enter / Esc cancels)
- `Related:` … a paired relation on both notes (deleting it on one side removes it from both at the next sync; not shown in BackLink). Choose `r` at the first selection in normal-note `zn` / `\l` / `za`. It preserves existing relations and body text, avoids duplicates, and repairs a missing reverse link. It is separate from the placement selection after `c`
- `\P` … put the current note (A) into the `Context:` of the linked note under the cursor (B), without asking. In visual mode, every linked note in the selection. Nothing changes for A itself, missing notes, or a B with unsaved changes
- Retired keys: `ca` / `cu` / `\ca` / `tt` / `ta` / `\at` / `\bc` / `zp` / `zap` (the functions and commands such as `:CA` remain; use the `c` flow and `\P` instead)
- `\l` (normal) … choose the note to put in with the mandala (`Enter` goes through, `gs` searches and centers, `e` decides, `q` cancels; the old fzf version is `:GnosisLinkPick`) → after choosing, pick where to put the link: `Enter`=end of the body / `i`=inline (right after the character under the cursor when `\l` was pressed, as is; no relation) / `t`=under a heading / `h`=below the cursor / `c`=Context (the current note into the target's `Context:`) / `a`=Context (the target into the current note's `Context:`) / `b`=ChildBranch / `p`=ParentBranch / `r`=Related (mutual) / `g`=put the current note into the chosen group (only when the chosen note is a group; it does not ask where to put it, it asks the display name and the reading, then ends) / `m`=merge (when one note is chosen) / `x`=swap the direction (write the link in the chosen note; when one note is chosen. `Enter` `i` `h` `t` pick the position inside the chosen note, and `p`⇔`b` and `c`⇔`a` are reversed). The screen heading is `Write a link to B in A` (A = the current note, B = the chosen note; long titles end with `…`). Other keys do nothing
- `\l` → `m` … merge the chosen note and the open note. Then choose the direction: `o`=merge the chosen note into the open note / `s`=merge the open note into the chosen note. The merged note's body goes to the end of the other note's body; its Context, BranchGroup and Related, and links from other notes (group members too) move to the other note (and its parent, if the other has none). The merged note is removed. The phone-memo import record is updated too, so it is not imported twice. `:GnosisMergeUndo` undoes the last merge (if a note was changed after the merge, it asks whether that change may be lost)
- `\l` → `e` → `g` … put the current note into the chosen group. Choose the group with `\l` (in the mandala decide with `e`; with the cursor in the note, pick in the `gs` screen and press `Enter`), then press `g`. It does not ask where to put it; it asks the display name and the reading (empty `Enter` = the note's title; names made only of hiragana, katakana or letters are not asked for a reading). Type and press `Enter` and it ends, and the group is sorted by reading (no confirmation screen). When the chosen note is not a group, `g` is not offered. Same with `za`. `\g` is gone
- the place choice of `\l` (after `e` in the mandala) … `q` / `Esc` only closes this choice and `\l` goes on (pick again in the mandala; `q` once more ends `\l`). `h` (under the cursor line) / `i` (after the cursor character) / `t` (end of the section the cursor is in) show the original note on the right: move the cursor there and press `Enter` to decide; `q` goes back to the place choice. Quitting a sub choice (`c` `a` `m` …) with `q` also goes back to the place choice
- `\l` (visual) … replace the selection with a link to the note chosen in the mandala view (`e` decides and shows the options: `Enter` = just the link / also relate with `p` `b` `c` `a` `r` `g` `m`; the display name is the selected text; no position is asked; `q` cancels)
- Auto-generated BackLink entries are different from the links you add here. Added links (also with display names) stay after saving and syncing
- **The name and reading list**: when you add two or more links to a group (or the Index) with `za` / `\l`, when you paste by hand and save, or with `:GnosisYomiReview` (everyone; reopen with `:GnosisReview`), a popup list appears. Choose a row with `j` `k` and press `Enter` to type its display name and reading (the fields hold the current name and a guessed reading, so `Enter` alone accepts them; the reading is asked only for names with kanji). **A row disappears from the list once you have entered it.** `s` keeps it as is (guessed reading), `A` keeps all the rest, `d` does not add it / removes it from the group, `q` / `Esc` stops (before adding, this cancels everything). Automatic members such as the guide and the time-series records are not asked about.
- `zg` changes **how this note is displayed inside a group** (the display name of the link to this note in the group's body). On a link in the note's `Group:` / `BranchGroup:`, it acts on that group; elsewhere, if the note is in several groups, you choose one. If there are several display names (`[B:aaa,bbb]`), you choose which one to change. ### Rules for relations, numbers and sync

- `語:` … mirrored as `(語):` on the other side
- `語:;` … the other side also gets `語:;` (no parentheses)
- `語;` … nothing is written on the other side
- `語::` … `語:` in the same section on both sides
- **Context is a `Context:` block at the top of the body (right after the H1 title)** (plain text line, not a Markdown heading; the links follow directly). A link added with `c` goes to the end of the existing links, and the same note is never added twice. The old `### Context` is still read (a note you add to with `c` moves to the new format without losing links; old-style notes are not rewritten just by opening them or syncing; migrate explicitly with `:GnosisContextMigrate` (current note) / `:GnosisContextMigrate all` (dry run) / `:GnosisContextMigrate! all` (whole vault)). A `Context:` inside a code block is not a Context
- Links to groups (`attribute: group`) go to `Group:`, links to normal notes to `Context:`, sorted by sync. Empty sections (ParentBranch / Group / ChildBranch / Related / BackLink) have no heading
- Children linked in the body are not written in `ChildBranch:` (the list in the body is the list of children; if you remove the link from the body, sync puts the child back in `ChildBranch:` from its `ParentBranch:`). Children in `BranchGroup:` are written. Inside `ChildBranch:`, children that have this note in their `Context:` come first, then one blank line, then plain children (sync reorders; the order within each part is kept)
- **Folgezettel numbers** (`folgezettel:` in the front matter) are assigned by sync. Notes listed in the Index body get the top-level numbers (`1` `2` `3` …), their Branch children `1a`, grandchildren `1a1` … (only for notes with one parent; for a note with several parents the parent is the one matching its current number, otherwise the first `ParentBranch:`).
- **Numbers always match the shape of the tree**: when the shape changes (re-parenting, deleting, adding), everything is recomputed on save and siblings continue without gaps as `1 2 3` / `a b c`. The order is by date for dated titles, otherwise by the current number, with new notes last. If nothing changed, nothing is rewritten (running it again gives the same result). Use `:UpdateMD` when you want to fix existing mismatches and gaps all at once.
- **A note that loses its place loses its number**: when a note is neither in the Index body nor in a diary and has no `ParentBranch:` (parent), sync removes its number (when you remove the parent or take it out of the Index). Its children (notes whose parent lost its number) lose theirs for the same reason. If you give it a parent again, it gets a new number (not the old one). A note that is only in a group and has no parent gets no number either, unless that group is the Index (`index.md`). `\a` (unassigned) lists only notes that have **no number and no parent** (a child whose parent has no number is not listed; a note with only `BackLink:`, `Context:` or `Related:` is listed because it has no parent).
- Groups (`attribute: group`) get no number (sync removes one if present), except groups made by branching (listed in a parent's `BranchGroup:`), which share the parent's number. A note without an ID is unassigned and appears in `\a` (`\N`). Old notes with only a Context can get their first Context as the parent with `:GnosisBranchFromContext`. With `:GnosisFolgezettelMove` on, `Ctrl-↑` / `Ctrl-↓` / `Ctrl-←` / `Ctrl-→` move to the parent, the first child and the previous or next sibling.
- Order in a note: `BranchGroup:` → `Group:` → `ParentBranch:` → `Context:` (blocks above the body, right after the H1; a block is only the link lines that follow it and ends at a blank line) → body → `ChildBranch:` → `Related:` → `BackLink:` (sections below the body). Empty ones are not written. `ParentBranch:` / `ChildBranch:` are relations set explicitly with `b` / `p`; sync neither adds nor removes them (it only follows titles and removes links to deleted files; never converts them to Context). `h` (below the cursor) with the cursor on one of these blocks puts the link in the body (never into the block)
- Synced automatically on save (`:UpdateMD` / `:UpdateAll` / `\ua` make everything consistent; `:UpdateAll` / `\ua` also sort index.md by reading)
- Labels are mirrored on the other side automatically. Remove the parentheses and edit by hand to make them sticky
- Links to deleted files are cleaned up automatically (whole lines; links inside sentences keep their text)

- `\1`〜`\9` … jump to the hub ・ `\H` … register the current note ・ `\0` / `\h` … list

### Vault encryption (gocryptfs)

- An encrypted vault is `A/note` (plain view) + `A/.crypt` (encrypted data) side by side. Gnosis asks for the password on start, mounts it, and locks it on exit
- `:GnosisMount` … mount by hand ・ `:GnosisLock` … lock by hand (unmount). A vault that another window or app is using is not locked (`:GnosisLock!` forces it)
- Several windows (Vim, the `\c` app) can open different vaults, or the same vault, at the same time. An encrypted vault is locked only when **the last window using it** ends (or switches to another vault). The registry lives outside the vault (`sessions/` in the Gnosis home), and entries of processes that crashed are removed automatically. If a note you are editing in several windows was changed elsewhere, autosave does not overwrite it: your unsaved content is backed up to `.state/conflicts/` and you get a warning
- `:GnosisBackup` `[destination]` … pack the project folder (`.crypt` and others; not the contents of `note/`) into a 7z with the vault password
- `:GnosisSetPassword` … encrypt an unencrypted vault, or change the password
- `:GnosisRemovePassword` … remove the encryption and go back to plain files
- `:GnosisExitCleanup` … cleanup on exit (writing viminfo etc.)
- `:GnosisChooseIndex` / `:GnosisChooseIndexDir` … choose the vault folder again by typing it (if `A/note` exists, it is always the root)
- Note: gocryptfs **refuses non-empty mount points**. Contents and file names are encrypted, but times, sizes and structure are visible
